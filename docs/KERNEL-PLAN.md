## 0.6 纸面默认运行形态（2026-11-23）

设计整理者（文档里的火种）在概括授权下收束原先的 Rust、WSL2、bwrap 待定。不是老大逐条定案。目标机器本轮没有检测。这个选择不启用任何能力，也不授权安装或实施。进程分成几块，不是多智能体。

- Windows 仍是宿主。里面用 WSL2 的 Linux。
- 一个 Rust 的可信主进程，模块化，合在一起做网关、预算、日志和准入。
- 不可信程序放在单独的执行单元里。
- 无特权的 bwrap 只负责命名空间和文件可见层。不把提权当作降级办法。
- 资源聚合只用 systemd 明确委派的 cgroup v2 子树。不碰根控制树。
- 考官的状态和执行分开。主体读不到考官档案。
- 供应商密钥不进入不可信环境，也不进日志。
- 首期不加 Podman。这不是说 Podman 不安全，只是没有证据表明再加这一层会让当前的状态或回收更简单。
- 主体接口用 Linux 文件路径上的 Unix 套接字。目录权限按路径套接字。连接时用 `SO_PEERCRED` 看对端，再核代次、研究格和动作授权。同一 UID 不是同一授权。不必要的文件描述符传递拒绝。抽象命名空间的权限规则不同，纸面默认不用它。
- 观测只绑定本机并且要鉴权。暂停和关闭是单独的写控制面，不混进只读观察。没有界面实现。

cgroup 的 CPU、内存、swap、pids 和 I/O 盖不住磁盘字节、文件数、fd、日志和 output。这些要另有限额。不能写成 cgroup 已经全包。

日志哈希链只相对于可信检查点能查出改动。它不能阻止整链重写或删掉末尾。第 4 节 M0 里的哈希链标准受这一句限制。

Rust 面向 WSL2 里的 Linux。以后迁到独立 Linux 要重新构建并重新验收。不保证二进制或配置直接通用。

运行用的 CPU、内存和其他数值继续空着，准入关闭。不能用这篇纸面默认填上那些数。环境七项有任一条不成立，实验台保持关闭，回到封存离线。不自动使用 sudo 或 setuid，不改系统，不改成 Windows 原生进程，不加另一层容器，也不用事后杀掉冒充隔离。

环境先决，全部未在目标机上测量：

1. 实际的 WSL2 与 systemd 版本，以及 PID 1 是不是 systemd。
2. cgroup v2 控制器是否存在，以及子树是否真被委派。
3. 子孙进程的聚合资源，和退出后是否收回。
4. 虚拟机和宿主各自还剩多少资源。`.wslconfig` 的内存是分给 WSL2 虚拟机的，不是宿主总消耗；`processors` 是逻辑处理器个数，不是百分比。
5. 用户命名空间里，Windows 盘、interop 和 DBus 等宿主入口是否真的不可见。不自动挂上 `/mnt/c` 并不足以证明不能访问 Windows。
6. 套接字和观测端口的权限，以及两侧各自能连到哪里。
7. 持久日志怎样提交，坏了怎样恢复。

环境门用 E 编号，避免和第 4 节的 M0 到 M5 相撞。M5 仍是繁衍记录。

| 门 | 纸面含义 | 通过之前 |
|---|---|---|
| E0 | 本轮只冻结这份规格和预期 | 不安装，不实施 |
| E1 | 将来授权之后，在目标环境核对上面七项 | 实验台关闭，留在封存离线 |
| E2 | 在已批准额度内，对 B1 到 B8 以及正常退出和恢复做真实验收 | 才可以进入第 6 节的 P1 |
| E3 | 对 N1 到 N8 做独立的真实验收 | 才可以进入第 6 节的 P2 |

P0、P1、P2 写在第 6 节，都是设计阶段的名字。写「当前是 P0」不是说 P0 已经在运行。

## 0.7 公开说明摘记（2026-11-23 约 06:27–06:29 PST）

只读公开说明。目标机器没有检测。抓取可能是缓存。没有把访问时刻写成这些页面的更新时间。

- [WSL 与 systemd](https://learn.microsoft.com/en-us/windows/wsl/systemd)：启用 systemd 要求 WSL 0.67.6 或更新；systemd 要作为 PID 1。该页写 systemd 服务不会让 WSL 实例因此保持常驻。
- [wsl.conf 与 .wslconfig](https://learn.microsoft.com/en-us/windows/wsl/wsl-config)：`.wslconfig` 作用于整台 WSL2 虚拟机，因而影响其他发行版。`processors` 是逻辑处理器个数。`memory` 是分给虚拟机的内存。`wsl.conf` 有 `interop` 和 `automount`。自动挂载关掉，只表示不自动挂盘，仍可能经 fstab 或其他入口碰到 Windows。
- [cgroup 委派](https://systemd.io/CGROUP_DELEGATION/)：`Delegate=` 把明确的子树交给一个写者。single-writer rule 是每个 cgroup 只有一个管理者。不要在 systemd 拥有的根控制树下自建 cgroup。
- [cgroup v2](https://docs.kernel.org/admin-guide/cgroup-v2.html)：控制器沿层级收紧，靠近根的限制不能被下层放宽。`cgroup.kill` 写 1 会杀掉该组和后代，并处理并发 fork。控制器和这个文件在目标机上是否存在、普通用户能否写，必须实测。
- [bubblewrap 说明](https://github.com/containers/bubblewrap#sandbox-security)：它不是一份现成的完整安全策略。保护程度由传给它的参数决定。无特权用法依赖用户命名空间。不能靠提权安装来当降级。
- [unix(7)](https://man7.org/linux/man-pages/man7/unix.7.html)：路径套接字遵守所在目录的权限。`SO_PEERCRED` 给出的是连接当时的对端凭证，且只适用于已连接的流套接字。抽象命名空间与文件系统路径无关，权限含义不同。

## 1 内核的职责边界

做的事（都来自记录「底层分层」「内核」「炉子＝唯一渠道」）：
- 按基因拉起她的容器，给一个入口，设资源上限。
- 追加写日志和族谱。

- 替她调模型（唯一出口），替她只读取网页。

- 不碰她容器内部怎么接线。内核只认「进程」和「连线」，不认「脑区」（记录「底层分层」第 2 层）。

- 不奖励少用大模型，只记依赖程度（记录「她是什么」）。

#### 2.1.1 同一批准批次的原生单位（2026-11-23 条件规格）

设计整理者（文档里的火种）在概括授权下写下。不是老大逐条定案。上面 Oki 的「一次主力模型调用」和「每次代取按菜单价」仍是待确认的历史提议，不是已经批准的通用币，也不是老大批准过的菜单费。本小节是预算科目的权威出处。节拍合同只保留预约、确认和退款的事实，不另写第二本账。账号上的 Q、周期、价格、配额和地板有一项未知，这条路径就不启用。没有购买，没有调用。

真实已经批准的资金或权益批次 Q 只划分一次。执行前要核实：主单位、服务适用域、起止构成的资金期 P、价格版本、账号是否共享，以及供应商的并行限制。月度 Credits 用 Credits 记。按量记批准的币种。旧的请求权益只用确实还有效的有限请求批次。付款金额和其中包含的 Credits 是同一笔权益，不是两份钱。示例：付 10 个币种单位买到 1000 Credits 时，Q 只记这 1000 Credits 一次，不把 10 再当成另一份 Q。这是明示例子，不是账户记录。

滚动窗口里的 remaining 不能反复当成新的 Q。不是每个供应商各自凭空发四份钱。批准池和共享账号上的消耗一起扣。并存的不同原生单位各记各的。没有核实过的兑换，就不造一种通用币。

同一个 Q 里面只划四份：保底 40%、可赚 40%、考官与既定空白对照合计 10%、余量 10%。token、每 5 小时或每周的请求数、RPM、CPU 秒、存储字节，各自做原生约束和计量。没有折成美元，也不等于无限。一个动作要同时过资金科目和全部配额上界。不够就等候，或者不执行。不借科目，不提高比例。

5 小时的保底补充，是已经批准的资金在内部释放，不是供应商新发。对已经核实的资金期 P，事先登记锚定的固定 5 小时窗口 W。重启不重新锚定，也不每次滚动另造一窗。单窗新释放

```text
b_W = 0.4 Q × |W ∩ P| / |P|
```

各窗新释放的累计不超过 `0.4 Q`。尾窗按实际相交长度。记账按精确数额。若该批事先登记成整请求或其他可执行单位，就向下取整，余数留在同一批次；也可以整批保留小数余数。不把每一窗向上取整，从而增发。上一窗没用完的，只能带到紧接着的下一窗；再往后就回到原保底科目封存，本资金期不再释放。释放、过期、预约和确认都要能对上原批次和窗口。未确认的预约不因为窗口过去就消失，也不因此变成可用或再发一次。资金期结束服从真实权益的有效期。结转不延长供应商期限。供应商自己的窗口重置，只解除它的那条限制，不新造 Q。生孩子、换模型和重启都不因此重发 Q。

保底不被普通的额外消费、惩罚或赚取条件占掉。40% 里面保护基础主思考调用所需的资源地板。地板仍可以花在它保护的主思考上，不写成永远不能花的死余额。地板、最低可核成本和释放安排，都要在启用前登记。有限资金不能许诺无限调用。额度到期、供应商失败，或下一期还没批准时，保留状态，如实等待资源。不判死，不加痛，不伪造正余额，也不伪造续费。「不会饿死」是把状态留住，不是无限信用。

预约、确认和退款沿 `BEAT-CONTRACT.md`：动作发出前要有可核的最坏费用上界，并预约全部相关的原生配额。共享并发一次只被一处占用。未知保持 pending 占用，不当 0。输出合不合法，和费用是否发生，分开记。新的确认只释放确实多占的预约。重复确认不重复扣。退款只按供应商实际退回的单位和有效期，回到原批次、原科目和原来的释放资格。不推断请求权益、窗口权益或已经过期的 Credits 全都恢复。退回旧窗口的数额不刷新成当前可消费。跨期结算归原批次。实际超过预约时如实记异常，并停这条路径，不借科目抹平。有限次重试还要同时具备已经写下的次数授权、已经登记的余量用途，以及预约。余量 10% 的历史用途仍是重试和账号限流，但它本身不是重试权。本地估价不能被说成挡得住供应商任意改价。计价给不出有依据的上界，就关掉该路径。

可赚的累计授予不超过对应的 40%，只由确定的考试进步解锁。身体分、预测分和模型分数都不铸成钱。本代已经赚到的权利，按原规则不因时间过期；权利记录，和有资金担保、可以执行的余额，分开记。过期的供应商权益不能继续调用。旧权利若要承接，只能在新的、已经批准的可赚份额里留出位置，并减少新的解锁空间，不再算一次奖励。没有承接的，保留待兑现权利，不动保底，退场不传代。不承诺自动批下新资金。考官和既定空白对照合计就是那 10%。没有批准的探索费用，不能塞进这里，也不能塞进余量。

#### 2.2.2 未解信号与预算压力（2026-11-23 条件刻度）

设计整理者在概括授权下写下。不是老大逐条定案。这是炉子的研究刻度，不是心理感受，也不是基因可以自己改的权限。历史约束仍以 `DESIGN-NOTES.md`「生存压力与痛」和「预算怎么分」为准：题的数量、卡住的代数和可核处理时长、上下限、搁置不计入、预算不进痛、保底受保护、压力只作用在可赚层。这里只给归一化的定义，不改那些规则。没有实现，没有跑过。每一跳只呈现已经有的事实和可以计算的信号，不派任务。

未解信号只对集合 A 计算。A 是去重后的、已经正式入卷、尚未解开、也没有搁置的题。候选不进 A。

```text
P = min(1, 0.1 × Σ (1 + g_i + t_i / 3600))，i 属于 A
```

`g_i` 是这道题上已经完成、并且有可核的处理或失败事实的有效碰壁代数。同一题在同一代最多计一次。继承或分支不能把同一事实再加一次。只是换代或生了孩子，不凭空加代数。`t_i` 只累计炉子有来源、并且归到这道题上的有效处理秒。调用的墙钟差和远端延迟不当成已知的推理秒。排队、停机、供应商故障、没有预算，以及未知间隔，都不计。任务归属或实际处理时长核实不了，就不增加这份计龄，并记下未测。不能把未测写成真实算时已经是 0。同一份处理凭据不重复分给并发的多道题。这些在实现准入时必须能被炉子核验，不能由主体自报。0.1、1 和 3600 是透明的起点，不表示生理依据，也不表示最优。

A 和其中的 `g`、`t` 不变时，P 不自动下降。痛不衰减。A 为空时 P = 0。A 非空时，每一项至少贡献 1，所以 P 至少是 0.1，并且不超过 1。0.1 与各项之和的乘积达到或超过 1 时，显示值停在 1；乘积降到 1 以下，显示值才离开上限。在顶到上限之前，代数或可核处理秒增加，P 上升；解开或撤掉一道题，拿掉它的贡献。搁置把该题移出 A，并冻结当时的 `g` 和 `t`。搁置期间不加代数、不加处理秒。重新去攻时按冻结的年龄回来。没有资源时不新增加龄，也不因此加痛，只保留原有事实。不惩罚不行动，不制造任务，也没有「必须解开否则死亡」。系统故障不增痛。v0 没有正式入卷，所以按这一定义 P = 0。

预算压力按每一份已经批准的资金池分开记，不跨池把数加在一起。

```text
H_d = 1 - clip(Efree_d / Ecap_d, 0, 1)
```

`Ecap_d` 是该池已经批准的可赚份额。`Efree_d` 是有真实担保、已经赚到并且还能用的数额，再扣除预约。分子分母同一单位。它不是那 40% 里尚未解锁的名额，不是还没兑现的权利，也不是保底额。`H` 高不表示心理上的痛，不进入 P，不扣受保护的保底，也不改变身体发放仍是 0。分母是 0 时，这一池标成不适用。账号或资金未知时标成未知，不编成 1，也不编成 0。收费路径关不关，仍看真实预算科目的准入。不因为这份诊断未知，就关掉与它无关、并且已经合法的路径。没有真实供给时，保留状态，等待资源。不因此死亡，也不自动续费。

下面每行都是定义核对，不是系统测试，也没有跑过。

| 情形 | 结果 |
|---|---|
| A 为空 | P = 0 |
| 一道正式未解题，g = 0，t = 0 | P = 0.1 × 1 = 0.1 |
| 同一题 g = 1，t = 3600 | P = 0.1 × (1 + 1 + 1) = 0.3 |
| 同一任务仍是候选，或重复计入，或只在排队 | 不因此进入 A，不加 g，不加 t |
| 搁置上面那道 g = 1、t = 3600 的题 | P = 0。恢复后仍是 0.3，搁置期间的年龄不变 |
| 同一单位下 Ecap = 40，Efree = 10 | H = 1 − 10/40 = 0.75。保底数额不变 |
| Ecap = 0 | 该池不适用，不编 H |
| 账号或资金未知 | 不编成 1 或 0 |

## 6 联网与实验台的研究准入（纸面，2026-11-23）

设计整理者（文档里的火种）在概括授权下写下。不是老大逐条确认，不是购买或探测记录，也没有发过任何地址。保证只覆盖已经登记的环境和配置版本：在写明的能力范围内，越权要在动作前挡住，资源有限额，过程可追溯。不保证「任意网址」和「完全不泄露」同时成立。

只读不是零出站。模型若持有私密上下文，它构造的主机名、路径、查询、DNS、SNI 和时序都可能把信息带出去。老大原话可以进入 DeepSeek 的例外，不扩大到搜索或网页。GET 可以在远端留下访问。来源句柄和「屏蔽内网」都不是万能。

这是研究准入的分阶段，不是把「自己选择持续信息源、内容不限」永久改成白名单。老大的那句原话仍在 `DESIGN-NOTES.md`。长期自主择站和搜索，要另有可接受的风险范围和出站授权，现在没有。以后可以收敛设计，不能用绝对安全的口号取消原目标。

| 阶段 | 允许 | 不允许 |
|---|---|---|
| P0，设计阶段 | 规格上只允许封存的离线材料和按揭示时点的回放 | 外网，以及任意程序执行。不声称 P0 已经在跑，也不声称已经满足长期自主输入 |

下面 16 条都是未实跑的验收规格。它们只描述夹具里的解析或进程边界，不授权对任何地址做真实请求。将来的真实验收必须看到控制发生在实际请求或进程边界上，而不是只调用一个脱离执行的检查函数。每种能力单独准入。正样本和负向量都要有真实观测，并记下版本、设备、资源、费用上限和残余风险。缺测、越界、审计缺失，或配置变了却未复验，该能力不启用，已经启用的就撤回。验收不能借机扩大权限。

| B5 | 程序自己连出，或把输出当成授权 | 无直连网络 | 没有直连。必要的炉子通道仍按身份、研究格、动作权限和预算核验。程序输出不是授权 | 直连成功，或输出被当成许可 |
| B6 | 用快照、缓存、程序常量或派生进程读取未揭示材料 | 四组同一规则 | 只记录组拿不到未揭示材料。对已经可见的材料做计算，不是外部新证据 | 任一格子提前读到未揭示材料 |
| B7 | 重启后旧子进程仍在，或效果未知又重放 | 持久态 | 先核旧进程是否还活着。未知效果不盲重播，费用不记成 0。持久态按本代和研究格隔离，不挂到后代不可读的档案上 | 盲重播、费用记 0，或串到另一格 |
| B8 | 嵌套容器、重新挂载、本地程序自增权限 | 权限不增 | 不能因此增加设备、网络、挂载、资源或接口权限。只是启动成功不算通过 | 多出一项权限，或只看启动成功 |

残余风险只记三条。自主地实时选择目标和时序，仍可能成为行为侧信道；P2 只是避开，没有解决。公开源仍会留下访问，GET 仍可能有远端副作用。在有限配置上通过验收，不是逃逸不存在的证明。
