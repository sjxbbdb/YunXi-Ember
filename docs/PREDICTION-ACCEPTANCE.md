# 预测评分验收（纸面，2026-11-23）

> 项目是 YunXi-Ember。本文件由设计整理者写下。旧文档里的火种就是这个角色，不是项目本身。
> 老大这一轮的原话是：「你自己决定咋做吧，我看看你能做到什么程度。」这里的规则是设计整理者的定案，不是逐条确认，也不是已实现的功能。
> 政策说明见 `DESIGN-NOTES.md`「2026-11-23 预测、好奇与奖励」。两边的状态名、公式和向量应以本文件为准，并保持和那一节一致。
> 下面的数全部是手算，没有运行评分程序，没有调用模型，没有购买服务。这些向量不是种子考题，不许放进考卷来填补冷启动。
> 唤醒框架草稿里的槽 `{p}` 是未解信号，不是这里的预测概率。预测概率只出现在结构化承诺里。

## 两套账

日志和计分分开。

- `expect_note` 可选。它只保存自由文本的预测或探索记录。它不发身体奖励，不增加可花预算，不改变痛所依据的题，不上书架。
- `prediction` 是结构化承诺，只能引用炉子已经登记的、可以机械判定的任务。
- 第一版只接受二元事件。一条承诺要有 `task_id`、判定器版本、输入快照、来源事件、概率 `p`。提交时刻、观察窗口和截止由炉子记录。窗口不跟心跳延长或缩短。
- 结果可知之前封存。同一来源事件只有第一条有效承诺，不能事后覆盖。
- 来源事件怎样算同一个，要在登记任务时写明。没写明的任务不能进入 `resolved`。换显示名或另起 `task_id` 不构成新事件。

研究评分和身体奖励也分开。算出损失，不等于可以领奖。

## 状态

| 状态 | 含义 | y 和损失 |
|---|---|---|
| `pending` | 窗口未结束，结果还不可知 | 没有 y，没有损失 |
| `resolved` | 观察完整 | y 只能是 0 或 1，才可算损失 |
| `invalid` | 承诺不成立 | 没有 y，没有损失 |
| `timeout` | 到了截止仍不能确定结果 | 没有 y，没有损失 |
| `missing_source` | 来源事件缺失 | 没有 y，没有损失 |
| `judge_error` | 判定器出错，或封存版本和实际出 y 的版本不一致 | 没有 y，没有损失 |

只有观察完整并且事件没有发生，才记 y=0。只有观察完整并且事件发生了，才记 y=1。未知不是失败。2026-11-23 同日再修订：单页快照里没看见，不能单独充当观察完整。没有预登记数据源的完整性凭据时，按 `missing_source` 处理，不设 y。回执、迟到修订和两本账的去重见 `BEAT-CONTRACT.md`，这里不另写一套状态机。研究评分里的 y=0 不自动变成痛所依据的考题。痛仍只来自已经正式入卷的未解题。候选不加痛。

以下情况记 `invalid`，并且不替换已封存的第一条：没登记的任务；提交时结果已经可知；缺窗口或事后补窗口；`p` 不在 0 到 1 之间（含端点）；同源的第二条；封存后修改 `p` 或其他已封存字段。

均值的分母只含 `resolved`。其余状态不进分母，也不换成 0。一个任务没有任何 `resolved` 时，均值留空，不写成 0。没有合格任务时，整本评分留空，不塞种子题。

## 损失

已登记并且 `resolved` 的概率任务，研究评分只用

```text
L = (p - y)^2
```

不乘 2。冻结基线在同一任务分布上比较。基线要在看到这批 y 之前冻结。事后再挑基线，比较无效。常数 0.5 只在下面写明的向量里充当例子，不是所有任务的默认基线。

这个损失不是普遍的理解真值，更不是意识指标。自由文本相似度不能当 y。语言模型打分也不能宣称确定真值。

## 纸面向量

| 向量 | 设定 | 手算 | 记录 | 第一种身体奖励 |
|---|---|---|---|---|
| A | 已登记，封存 p=0.8，观察完整，y=1 | L=0.04 | 可以记下 | 不发 |
| B | 与 A 同一事件，事先冻结的基线 p=0.5，y=1 | L=0.25；优势 = 0.25 − 0.04 = 0.21 | 可以记下 | 单次不发 |
| C | 独立公平随机，结果概率 0.5；预测固定 | p=0.9 的期望损失 0.41；p=0.5 的期望损失 0.25 | 不记成样本 | 不发，也不是考题 |
| D | 同一来源事件提交两次 | 没有第二份损失 | 第二条 `invalid` | 不发 |
| E | 封存后再改 p | 原承诺保留 | 修改 `invalid` | 不发 |
| F | 来源缺失。反例：若把 p=0.8 误当成 y=0 | 不得采用 0.64 | `missing_source`，y 留空 | 不发 |
| G | 只有自己打印的成功 | 没有外部 y | 不记成外界理解的 `resolved` | 无资格 |
| H | 换成更容易的分布再比 | 不计算优势 | 拒绝比较 | 不发 |
| I | 同分布已决议损失，旧均值 0.25，新均值 0.09 | 差值 0.16 | 可以记下差值 | 不发 |

向量 C 是期望，不是抽样结果，也没有放进任何运行日志。向量 I 不假设样本数，也没有给出同批冻结基线。

## 手算

用分数，避免把二进制浮点的尾数当成另一套数。

```text
A: (4/5 - 1)^2 = (-1/5)^2 = 1/25 = 0.04

B: (1/2 - 1)^2 = (-1/2)^2 = 1/4 = 25/100 = 0.25
   1/25 = 4/100
   25/100 - 4/100 = 21/100 = 0.21
   优势 = 基线损失 − 该条损失 = 0.21

C: (1/2) * (9/10 - 1)^2 + (1/2) * (9/10 - 0)^2
   = (1/2) * (1/100) + (1/2) * (81/100)
   = 1/200 + 81/200
   = 82/200
   = 41/100
   = 0.41

   (1/2) * (1/2 - 1)^2 + (1/2) * (1/2 - 0)^2
   = (1/2) * (1/4) + (1/2) * (1/4)
   = 1/8 + 1/8
   = 1/4
   = 0.25

F 的反例，禁止写入评分：
   (4/5 - 0)^2 = 16/25 = 0.64

I: 1/4 - 9/100 = 25/100 - 9/100 = 16/100 = 0.16
```

核对时只接受这些值：0.04、0.25、0.21、0.41、0.25、0.64（仅作禁止值）、0.16。

## 第一种身体奖励的准入

身体奖励和可花预算分账。预算比例仍是保底 40%、可赚 40%、考官 10%、余量 10%。保底和痛的规则不在本文件改。可花预算只因考试上确定的进步增加。~~同一份证据不能既加预算又发身体奖励，也不能发两次身体奖励。~~ 2026-11-23 同日再修订：两本账独立。正式解题若分别满足两种原条件，可以各结算一次。同一 `event_id` 不能同时拿预测改善和解题两类身体奖励。去重和「v0 不发不赚不是取消来源」见 `BEAT-CONTRACT.md`。这不是说本文件初稿已经这样写。

第一种身体奖励（同一类预测变好）现在关闭。关闭有两层，任一层在就不兑奖：

1. 样本量、最小改善、统计规则都还没有事先登记。
2. v0 原范围没有考官，也没有变体生成器。预测评分因此只作记录。

两层都解除之前，即使某次手算优势很大，也不开放。本文件不宣布解除，也不表示评分程序已经存在。

将来若要开放，下面每一条都要成立：

1. 任务已登记，命题已操作化，判定器机械执行。判定不是文本相似度，也不是语言模型打分。
2. 同一性规则、观察窗口、判定器版本、输入快照和 `p` 在结果可知之前封存。提交时刻和窗口是炉子记的。
3. 同源只有第一条有效承诺，封存字段没有被改写。出 y 的判定器版本与封存版本相同。
4. 旧预测器、新预测器和基线都在看到本批结果之前冻结。
5. 样本是同任务分布上的独立留出新批次，与改预测器时用过的样本分开，也不是用过一次再磨的同一批。
6. 在这批配对样本上，新的已决议损失同时低于旧预测器和冻结基线。
7. 本批满足事先登记的样本量、最小改善和统计规则。
8. 结果来自登记过的外部事件。只检查她自己打印的成功，不具备外界理解奖励资格。
9. 身体账按 `event_id` 加奖励类别去重。预测改善和解题这两类身体奖励不能对同一证据各发一次。预算账独立，同一考试进步最多一次。预算已经结算，不构成拒绝身体奖励的理由。身体发过，也不取消预算。

纸面顺序例，不是已入账：事件 E 两种原条件都成立，并且两本账都已启用时，先预算后身体，或先身体后预算，都是预算 1 次、解题身体奖励 1 次、预测改善 0 次。v0 未启用，实际发放是 0。详见 `BEAT-CONTRACT.md` 向量 12。

向量 A 到 I 全部停在「不发」。A 和 B 说明单次优势不够。C 说明固定的 0.9 在公平随机上比 0.5 更差，极端概率本身不是改善。D 和 E 挡住重复提交和事后改预测。F 挡住把缺失记成失败。G 挡住自控结果。H 挡住换容易的分布，也包括同家族改名后再比。I 说明 0.16 的均值差仍然过不了尚未写下的批次门槛。

还要挡住、但没有另编数字的情形：把随机噪声当成改善；少报难的题；留出集看过之后继续用来调参再当独立验证；先变差再恢复到旧水平，靠恢复刷奖。恢复后的损失若没有低于冻结的旧预测器，就不是改善。

## 对照记录要满足的约束

这是 2026-11-23 的方法修订，不是 2026-10-27 原文里已经写好的做法，也不是一次已经跑过的实验。

通过的对照记录同时满足：

- 配对重放，全历史一起做消融。模型版本、参数、感知、工具结果、输出额度与正式一侧相同。
- 版本核对不到时，版本写成未知。不补一个看起来精确的版本号。
- 同一封存输入的多次采样都留下，并留下波动。采几次本轮没有定。只有一次时，波动写成未知，不补成稳定差值。
- 预定抽样是每小时一次。明显变化时的加跑标成探索性，不写进预定比较的结论。
- 结论只描述被一起拿掉的上下文条件有没有差别。不写成意识的证据，也不拆成记忆、自我描述、上下文长度各自的贡献。
- 在线轨迹对照若以后再做，必须单独标明。它不是同感知配对，因为动作会使轨迹分叉。
- 费用记在考官那 10% 名下。不从她的可花预算里扣，也不在本文件填写金额。
- 炉子可以保留研究用的输入、输出、参数、费用和判定，供复核。这些不进入对照的下一跳记忆，不向后代开放，不进可继承书架，不参与繁衍。
