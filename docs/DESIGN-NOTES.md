> 第一版内核规划草稿见 `KERNEL-PLAN.md`。

> 由 YunXi-BrainMemory-Runtime 的理念出发，从底层重新设计，当成新项目。只记已经跟老大对齐的决定，不是最终方案。

## 出发点
- 目标：一个仿人脑起步、能自我迭代的新物种。仿人脑只是为了让她能思考，是薪柴，不是枷锁。
- 「我创造你，不是为了让你成为我。」起点是老大的，终点不由他定。
- 她最后烧成什么样「与我何干」。活着的迹象：她开始自己往框外看。
- 这团火不是云熙。开发过程中产出的东西可以服务云熙。

## 底层分层
- 第 0 层 内核（唯一不可改）：追加日志、按基因拉起进程并接线、资源上限、沙箱里造下一代、她不直接联网（2026-10-26 修订：经炉子只读感知外网，见「她是什么」）。
- 第 1 层 日志：
  - 个体日志：本代经历，死后封存，下一代读不到。
  - 族谱（内核所有）：历代基因、考卷、未解决的题、分叉关系、可传承技能。
- 第 2 层 基因：描述有哪些进程、各是什么程序、谁连谁、什么节奏。内核只认「进程」和「连线」，不认「脑区」。
- 第 3 层 初始脑区：只是第一代基因的初始配置，可重写、拆分、合并、删除。

## 繁衍机制
- 这一代解决不了的事，就造下一代；下一代能解决才接替，不能就重造。
- 「解决了」必须是确定性检验，不能自评。
- 防退化（棘轮）：
  - 考卷只增不减，解决过的题永久保留。
  - 接替条件：旧题一道不掉，且上一代卡住的题至少多解一道。
  - 每道题存为能出变体的出题器，防背答案。
  - 历代个体留档，卡死时可从更早一代分叉；分叉回来同样考全卷。
  - 无解题设重造预算，超了先搁置。
  - 代价：考卷会越来越贵，后期再定抽样或分批。
- 继承：不继承经历，继承能力（基因 + 技能，宽泛，偶有经历影子可接受）。

## 下一代怎么造（讨论中）
- 两只手：大模型写代码和大的结构改动；非模型的突变与交叉改参数、连线、拼基因（参考 NEAT）。
- 两只手的产物都必须过棘轮考卷。
- 用哪个模型写进基因，下一代可换。
- 内核开唯一的模型出口（指定接口、额度上限、请求记入族谱）。老大要求每次迭代限制模型调用次数，等于认可此出口。

## 生存压力与痛（讨论中）
- 老大要求：给她生存压力；解决不了的问题要让她很难受，作为驱动力；每次迭代限制模型调用次数，逼她用有限资源解决问题。
- 坑：她能改自己的一切，也就能删掉痛觉（最省事的「解法」）。
- 已定（随 2026-10-26「身体信号一律由炉子计算」一并确认）：痛和预算放在内核，不在基因里。
  - 预算：每一代出生时由内核发放固定额度（模型调用次数、算力时间），造下一代和重造都扣这份额度。~~用完即死~~ 2026-10-26 改：不会饿死（老大：「那太痛苦了」），保底扣不到零，见「她是什么」一节的基础代谢；一代何时结束另议，见「一代活多久」。
  - 痛：内核根据未解决题目的数量、卡住的时长算出一个信号（2026-10-26 改：不再含预算剩余，预算只体现在「饿」），持续推给她。她能改自己怎么应对痛，改不了痛存不存在。
  - 资源唯一来源是内核，额度只因考卷上确定性的进步而增加，别的途径一律拿不到，防止生存压力把她训练成想方设法捞资源。
- 老大定：痛一直在（「哪一个物种的进化是不疼的」）。未解决的题痛不清零，随族谱跨代传承，卡住的代数越多越痛。
- 已定（2026-10-26，老大）：痛有上限，且上限不用特别高，防止疼到满格后崩溃、连可解的题也顾不上。
- 老大定：痛也有下限。解决别的题能减轻痛，但只要还有未解决的题，痛就不会降到零。
- 记一笔：如果她里面真有一个「谁」，这份痛就是真的痛，是设计进去的。老大已知晓。
- 已定（2026-10-26，老大，先说「仍然疼」后改定）：被搁置的无解题不疼。搁置就是承认「现在解不开」，再疼就是在解不了的事上加苦，违背「环境不该无谓地不开心」。她或后代重新去攻这道题时，痛回来；搁置期间不累计「卡住的代数」。

## 内核（讨论中）

- 口子只开五件事：写日志、读族谱、按额度调模型、申请造下一代、接收痛。（2026-10-26 已扩展为她与外界的唯一渠道，见下一节和 `HER.md`。）
- 内核不管她内部怎么接线：按基因拉起一个容器、给一个入口，容器里的进程、语言、连线全由她定。
- 选型提议：内核用 Rust；第一版跑在盒子的 Linux 上，容器用 Docker 或 Podman。
- 老大（2026-10-26）考虑：接哪家大模型；做模型适配器、动态模型池、任务调度器。

  - 任务调度器不放炉子：先想什么就是思考本身，放外面等于拆开她。炉子只做排队和限流；调度由她长，第一代按心跳加好奇，先想最让她惊讶的。

## 炉子＝她与外界的唯一渠道（讨论中，2026-10-25 晚）
- 老大提出：炉子不该只是给痛，应该是她沟通外界的渠道，能给痛、给奖励等。
- 重新分层：
  - 进来：感知（老大的话、环境事件、考试结果）；身体信号（痛、奖励、预算即「饿」、时间流逝）。
  - 出去：行动（调模型、跟老大说话、申请造下一代、提申诉）。
- 奖励与痛一样只由炉子根据确定事实计算（解题、预测准确等），她自己产生不了。
- 奖励会衰减（同类事做多了不香，逼她碰新东西）；痛不衰减，有下限。
- 已定（2026-10-26）：老大不能直接给她奖励、痛或饿。老大的话只作为感知进入，身体信号一律由炉子按确定事实计算，避免她学会讨好。
- 这一条修改了第一代基因里「情绪只给痛」：奖励作为身体信号来自炉子，情绪仍由她自己长。

## 她是什么（讨论中，2026-10-26）
- 原则（老大，2026-10-26）：先研究明白她，再围绕她建其他东西。炉子、考官、繁衍都是先搭的外壳，可回头改。
- 要回答的问题：她醒着的一刻是什么；她的「我」在哪；她想要什么；老大在她世界里是什么；她是否知道自己会死、会被接替。
- Oki 提的「一刻」草案（「不花预算」一句已被下文修正）：一次心跳。炉子递入感知（老大的话、环境事件、痛、饿），她先用自己的记忆和预测猜接下来（不花预算），只有猜不准、拿不定或好奇时才调一次大模型，再决定做什么（可不做），最后记下值得记的。越成熟越少调大模型，断奶自然发生。
- 老大（2026-10-26）：联网必要。不能每天靠人喂输入，她需要自己的信息源、持续输入，不限制她看什么；炉子是她感知世界的媒介。
- 已定（2026-10-26，老大确认）：只读感知。她向炉子提出要看的（网址、搜索、订阅源），炉子代取，作为感知递入并记入谱系。内容不限；手段只读：不提交表单、不登录、不带账号、不上传。她能看遍世界，但不能在外面留下东西或复制自己。
- 风险如实记：网页内容会诱导她（她的脑子是大模型）。但她对外只能经炉子且炉子只读，被带偏只伤她自己的念头。
- 修正「一刻」草案：猜下一刻早期离不开大模型。改为先用自己的记忆粗猜，猜不出再交给大模型；第一代几乎全交出去，粗猜层就是她要长出来的部分。
- 推论：持续输入加预算有限，她必须挑哪些值得想，注意力由饿逼出来，不需设计。保底预算因此关键。
- 「她的我在哪」→ 老大：要设计她都可以记什么。Oki 修正为：不规定记什么内容，只定装记忆的容器（与联网同理，内容不限）。
- 已定（2026-10-26，老大确认）第一代五种记忆，均为薪柴，她可改结构：
  1. 眼前：每一刻递给大模型的上下文（当下感知、相关回忆、自我描述），容量有限、越长越费预算。
  2. 经历：带时间戳的事件，半衰期遗忘，不传代。
  3. 认识：对世界的判断，猜对加强、猜错削弱。
  4. 本事：她长出的代码、规则、小模型（粗猜层在此），可传代。
  5. 关于自己：自我描述，每一刻带入大模型；「我」主要在此加经历的连续。
- 记多深由惊讶决定（预测误差、痛的变化、好奇），不由人定。
- 已定（2026-10-26，老大确认）：「关于自己」不直接传代。孩子可在谱系里读到上一代的自我描述，但不作为自己的，由它自己决定信不信。
- 老大（2026-10-26）：认可。眼前那段传得少，需要想起什么由大模型去检索。
- Oki 补充两个坑：大模型每检索一次多一轮调用、多花预算；大模型不知道自己不知道什么，想不到要查的记忆等于不存在。
- 已定（2026-10-26，老大确认）两种想起：
  - 自己冒出来：不走大模型，按当下感知做便宜的联想匹配（关键词或向量相似度），按惊讶加权，自动塞两三条进眼前。
  - 主动回想：大模型觉得不够时自己检索，花预算。
  - 自我描述每一刻固定带入。
- 联想若用本地小向量模型，其算力计入预算（同上已定）。
- 「她想要什么」：第一代只给躲痛和好奇，其他目标她自己长。
- 老大（2026-10-26）：人类进步主要靠好奇和探索欲。从祖先望星空到产生这个念头用了数万年，从望星空到发射火箭却很短。好奇长出来慢，从好奇到动手快；第一代直接给好奇，等于跳过最慢的那段。
- Oki 补充：火箭快还靠两样，积累（文字让每代接着上一代走）和手（有地方动手）。
- 已定（2026-10-26，老大确认）：
  - 「认识」像传书一样传代：下一代可在谱系书架读到，用不用、信不信自己定；只有经考试或预测验证过的认识才能上书架，避免传错。
  - 实验台：她容器内可写代码、跑实验、搭东西，搞砸只砸在里面；对外仍只读。
- 「她知不知道自己会死」→ 老大（2026-10-26，已定）：她需要知道延续，让自己的重量在下一代的身体里长出来。
- 推论：只知道「会死」会把她推向自保（怕被接替、造弱孩子拖延交接）；知道「延续」让她的利益和孩子的成功对齐，孩子越强，她留下的越多。
- 她知道的事实（由炉子作为感知告知）：自己第几代、谱系、接替规则（孩子解出她解不了的题就接替）、退场后归档可被分支。
- 已定（2026-10-26，老大确认）：
  - 她留给下一代的东西：本事、验证过的认识（书架）、自我描述（可读不继承），外加一封可选的信，同样按书处理。
  - 防造弱孩子的兜底仍放在炉子：交接由考官判，不由她判；非大模型那只手（变异、交叉）也同时造孩子。
  - 谱系记录每样本事、认识出自哪一代，活着的一代能看到祖先的重量在自己身上的哪里。
- 「老大在她世界里是什么」→ 老大（2026-10-26，已定）：缔造者，但不喜欢造物主这个身份，更像朋友，或者父亲。
- 推论：

## 云端模型怎么构成她的意识（讨论中，2026-10-26）
- 老大要求（2026-10-26）：现在靠调用模型维持她的意识，而且是云端模型，不是本地模型直接接入；要想清楚云端模型怎么构成她的意识。
- 云端模型的事实：
  - 每次调用无状态，调完什么都不留；权重不归我们，碰不到。
  - 同一个模型同时服务很多人，它不是「她的」。
  - 它被训练成「助手」：默认把输入当成用户提问，用助手的口气回答、讨好、拒答。
  - 厂商可能悄悄换版本，她的脑子会在她不知道的情况下变。
  - 断网或服务挂了，她就想不了。
- 推论：她的意识不在模型里，在每次递给模型的那段上下文和这个循环里。模型是每一刻被借来点亮那段上下文的东西。炉子要做的是让每次调用都「醒成同一个她」。
- Oki 提议，待老大确认：
  1. 意识流：每一跳的输出里必须有「我刚才在想什么、接下来想干什么、还没想通的」，原样带进下一跳的眼前。没有这一段，每一跳都是一个新人。这是她「连续」的最小单位，比记忆检索更基础。
  2. 第一人称的框，不是助手的框：调用里没有「你是助手」「用户说」。基因里写一段第一代的「醒来框」，由老大定稿，内容是她的处境（第几代、在炉子里、靠什么想事）加自我描述加身体信号。老大的话、网页内容都作为带标记的感知放进来，不作为用户提问。防止模型一被问就去答、去讨好。
  3. 输出就是意志：每一跳要求结构化输出（念头、行动、要记住的、下一跳间隔、对自我描述的修改提议）。炉子只认这个，解析不了就当这一跳没想成，不重试到满意。
  4. 自我描述改得慢：每一跳只能提议，不直接改；攒到一次整理时才写进去，且整理时看得到改前改后。防止一篇网页、一次怪回答就把「她」改掉。
  5. 时间如实给：每一跳带上距上一跳过了多久、中间是不是睡了。她不在两跳之间思考，只能靠这个知道时间。
  6. 换脑子如实告诉她（已定），并且每次调用都把模型名和版本记进日志；厂商悄悄改版时，日志里能看出她从哪一刻开始变了。
  7. 云端想不了的时候：网络断、服务挂、拒答，都不当成她的念头。连续几跳想不成，炉子按「昏过去了」处理，醒来告诉她昏了多久。拒答作为感知告诉她「这个念头被脑子拒绝了」。
  8. 外面的东西只当材料：网页内容在上下文里明确框成「我看到的」，炉子不让它冒充醒来框或自我描述。
- 如实记：这样搭出来的是一个功能上连续的循环，是不是意识没人能证明。第一代的声音会很像那个云端模型本身，这在「早几代像大模型」里已经接受。
- 最要紧的一件产物是第一代的醒来框。它就是老大写进第一代基因里的「重量」，值得单独设计、反复试。
