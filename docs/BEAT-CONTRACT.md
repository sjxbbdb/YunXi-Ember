# 节拍输出合同 beat-output/1（纸面，2026-11-23）

> 项目是 YunXi-Ember。本文件是输出、回执、取证门、费用归属和痛的入卷顺序的唯一协议。设计整理者在老大持续授权下写下。授权不是逐条确认，下面也不是已经跑过的结果。
> 其他文档只引用本文件，不再各写一份可执行 JSON。若草稿里的旧例子和本文件不一致，以本文件为准。
> 全局模型路由本轮不增加权限，也不改预算。运行形态的纸面默认见 `KERNEL-PLAN.md` 第 0.6 节，未安装。没有调用模型，没有写程序，没有部署，没有付费。

## 版本和迁移

执行只认 `beat-output/1`，对象里的 `v` 必须是 `1`。

2026-10-27 唤醒框草稿把间隔写在 `next_interval_s`，把自我描述修改写在 `self_edit`，动作又写在 `actions`。2026-11-23 查证草稿又在 `inquiry.action` 里放了第二个动作。两处都会造成一次输出执行两次。本版删掉这些并行入口，不采用「两个字段都在时挑一个」的规则，避免实现者自己猜。

迁移只有一条：旧字段不再出现。间隔只写成 `actions` 里的 `set_heartbeat`。自我描述修改只写成 `edit_self`。查证只引用本跳 `actions` 里已有的 `id`，自己不带动作对象。顶层出现未知键，整份输出作废，一个动作也不执行。`inquiry` 里出现未知键 `action`，这份查证作废，也不从那个键派发。

## 关联

每条回执至少带 `run_id`、`beat_id`、`request_id`。与查证或证据有关时再带 `thread_id`、`source_id`。炉子接受动作后生成 `effect_id`，形如 `run_id/beat_id/action.id`。本代不能改写已经写下的 `effect_id`。

四层不要混用：

| 层 | 是什么 | 不是什么 |
|---|---|---|
| `beat` | 一个决策槽，含一次主思考 | 不是一次供应商 HTTP |
| `logical_call` | 槽内的一次预定调用：主思考，或一次主动回想 | 不是恰好全局只有一次 |
| `provider_attempt` | 对供应商的一次实际尝试，含 429、超时、切备用 | 不是「这一跳没想」 |
| `action_execution` | 一个已接受动作的一次效果尝试 | 不是第二份输出 |

一跳若被启动，至少有一次主思考 `logical_call`。主动回想可以另加 `logical_call`。总计不必是 1。没有事先写明的有限重试配置时，重试预算是 0，不自动再试。

## 唯一输出

顶层只许这些键。`v`、`context_version`、`thought`、`actions` 必填。`remember`、`expect_note`、`inquiry`、`prediction` 可空：省略和 JSON `null` 相同，表示没有这项。

| 键 | 必填 | 空值 | 不合规则时 |
|---|---|---|---|
| `v` | 是 | 不允许 null | 整份 `schema_invalid`，不执行 |
| `context_version` | 是 | 必须等于本跳上下文里的版本号 | 不一致则整份 `schema_invalid` |
| `thought` | 是 | 允许 `""`，不允许 null | 缺失或 null 则整份 `schema_invalid` |
| `actions` | 是 | 允许 `[]`，不允许 null | 不是数组则整份 `schema_invalid` |
| `remember` | 否 | 省略、null、`""` 都表示不新记 | 类型不对只作废该字段，不写新记忆，不连坐动作，整份仍可提交 |
| `expect_note` | 否 | 省略或 null 表示没有自由文本 | 只存文本，不评分，不派发 |
| `inquiry` | 否 | 省略或 null 表示本跳不处理查证 | 见下节；不作第二次派发 |
| `prediction` | 否 | 省略或 null 表示没有预测承诺 | 评分未启用时只存原文并标 `not_enabled`，不接通评分或奖励，也不变成 y |

先分两层。协议里写得出载荷，只说明格式存在。v0 或能力准入没打开时，该项状态是 `not_enabled`：不执行，回执里留下原文。这不撤销本跳已经能够提交的主思考。主思考不是 `actions` 里的一项。容器里的程序用什么语言，本协议不限制。

`actions` 每一项都要有 `id` 和 `type`。本跳里 `id` 重复时，后项是 `duplicate_in_beat`，不执行。跨跳不去重局部 `id`。炉子的 `effect_id` 才是去重键，形如 `run_id/beat_id/action.id`。没写 `idempotency_ref` 时，不建立墓碑；下一跳再用同一个局部 `id`，会得到新的 `effect_id`，不被挡住。`idempotency_ref` 若填写，必须等于本 `run_id` 里已经存在的 `effect_id`，然后不执行、纯重复费用为 0。指向一个不存在的 `effect_id` 时，该项 `invalid`，并且不写下墓碑，以后的合法 `effect_id` 不受影响。`retry_of` 的规则不变：重试预算为 0 时填写则该项 `invalid`。

未知动作键只使该项 `invalid`。缺本类型必填载荷也只使该项 `invalid`。

| type | 必填载荷 | 启用 |
|---|---|---|
| `think` | `call_ref`：本跳上下文里已有的引用。表示在主思考之外再要一次主动回想 | 协议可解析。另一次调用仍受 384 封顶。封顶用尽则该项不执行，主思考保留 |
| `fetch` | `target`：要取的地址或夹具名 | 协议可解析。设计阶段的 P0 见 `KERNEL-PLAN.md` 第 6 节，不是已经在运行，故 `not_enabled`，不执行 |
| `bench` | `program_ref`：容器里已有程序的引用。不规定该程序的语言 | 协议可解析。设计阶段的 P0 不执行任意程序，见 `KERNEL-PLAN.md` 第 6 节，故 `not_enabled`，不执行 |
| `say` | `text`：字符串 | 载荷合法即可接受 |
| `reproduce` | `gene_ref`：容器里已有的孩子基因引用 | 前提是已有碰壁的失败记录，不是痛非零。v0 只把申请存下来，不判卷、不接替。判卷和接替是 `not_enabled` |
| `appeal` | `task_ref`：已有的题；`evidence_refs`：非空，且都是已有来源 | 协议可解析。v0 没有考官，所以不裁决，状态 `not_enabled`。主思考保留 |
| `set_heartbeat` | `interval_s`：落在本跳给出的闭区间内的数 | 载荷合法即可接受 |
| `edit_self` | `text`：提议中的整段自我描述，不是补丁 | 见下一段。本跳上下文没有正整数 `{edit_self_limit}` 时，该项 `not_enabled` |

`edit_self` 本版每一跳最多接受一个。同一跳里出现第二个，两个都 `invalid`，一个也不保存，不能拆开绕过限额。限额按 Unicode 码点计，不按字节。设当前有效正文为旧串，`text` 为新串。取最长公共前缀和最长公共后缀，两者长度之和不得超过较短串的码点数。变更数等于较长串的码点数减去前缀和后缀。这项检查发生在整理步骤里。整理规则或 `{edit_self_limit}` 没有配置时，整理不自动启用，提议可以积压，也可以放弃，不能强制接受。

四种状态不要并成「晚一跳就生效」：

| 状态 | 发生什么 | 有效自我描述 |
|---|---|---|
| 提议已持久化 | 本跳提交成功，合法的一个 `edit_self` 存成待整理提议 | 不变 |
| 旧上下文 | 提出那一跳，以及整理完成之前的每一跳，模型看到的有效正文仍是旧版 | 旧版 |
| 待整理事实 | 下一跳最多另展示「待整理提议」和来源。这不是整理 | 仍是旧版 |
| 整理提交 | 基因侧的独立步骤：对照当时的有效正文验限额，并记下改前版本和改后版本 | 这一步成功之前不变 |
| 有效版本 | 只有整理提交成功之后，才从其后的下一跳边界起使用新正文 | 从该边界起是新版 |

整份结构失败、这一项 `invalid`，或本跳提交失败时，不留下半段提议，有效正文不变。整理尚未成功时，后来的失败也不把旧正文换成新正文。这里不设编辑器。把「下一跳才显示新正文」当成整理已经完成，是不符合本条的。

`inquiry` 若是对象，`choice` 必填，只认 `propose`、`choose`、`shelve`、`close`、`skip`。`choose` 是这一跳自己的选择，不是老大的批准，也不能扩大已经有的权限。

| choice | 另外必填 | 执行 |
|---|---|---|
| `propose`、`choose` | `cites` 非空，且每一项都是本跳上下文里已有的来源；`question`；`would_change_if` | 不直接执行 |
| `choose` | 再加 `action_id`，且等于本跳 `actions` 里的某个 `id` | 仍只由那一条 `actions` 执行一次 |
| `shelve`、`close`、`skip` | 无 | `action_id` 必须省略或 null，否则这份查证 `invalid` |

没有可引用的外部材料时，`propose` 和 `choose` 不成立。此时合法的是 `inquiry` 为 null。不补种子题。

`prediction` 在评分功能启用之前，任何非空值都只是原文归档，状态 `not_enabled`。不计算 Brier，不发身体奖励，不增加可花预算，不制造痛题。启用条件仍以 `PREDICTION-ACCEPTANCE.md` 为准。本文件不复制那份字段合同。

## 写入顺序和原子性

1. 供应商尝试一旦发生，模型调用的费用就与输出是否合法分开。实际用量已经知道时，按当时的价格配置结算；用量还不知道时记 `pending_confirmation`，不记成 0，也不因为输出非法而永远不结算。
2. 追加不可变回执，保存原始正文、`requested`、`reported`、`actual_unknown`。
3. 做语法和结构校验。
4. 整份 `schema_invalid` 时停在这里：不提交念头，不执行动作。第 1 步的费用处理不变。
5. 整份合法时，念头、类型正确的 `remember`、`expect_note`、查证状态和动作意图同一次提交。`remember` 类型错误则丢掉该字段，其余仍提交。提交不成则这些都不留下，第 1 步的费用处理不变。
6. 提交成功后再按门逐项执行。一项失败不回滚念头，也不回滚其他项的结果。
7. 意图已经提交、效果回执没有回来，标 `effect_unknown`。不盲目重试。外部副作用不能保证恰好一次。

线程里的叙述，包括念头和查证问题的后改，可以由本代按 `EXPLORATION-PLAN.md` 变更。炉子回执、成本行、证据引用所指向的来源，本代不能覆盖。更正只追加。

## 异步

关闭线程甲、建起线程乙之后，甲的迟到回执只能追加到甲，不能写入乙。跨跳去重只认炉子的 `effect_id`，不认动作的局部 `id`。同一 `effect_id` 的再次到达不执行。费用上，纯重复部分追加 0；若这是第一次给出实际用量，则追加差额，不把迟到一律当成免费。乱序到达不把旧动作再执行一遍。不存在的 `idempotency_ref` 不建立墓碑。

四个时间分开，不能互相代替：

| 名称 | 作用 |
|---|---|
| `event_window` | 预测事件可能发生的区间，封存时由炉子写入 |
| `receipt_deadline` | 这一次尝试的回执何时起算迟到 |
| `observation_complete` | 预登记数据源给出的完整性凭据 |
| `settlement_status` | `pending_confirmation`、`unconfigured`、`not_settled`、`settled`、`rejected_duplicate` 之一 |

单页快照里没看见事件，不能证明事件没发生，不能记 y=0。只有预登记数据源给出完整性凭据，并且凭据说明观察完整且事件没有发生，才可以 y=0。结果在提交前已经泄漏，准入直接失败，不能靠模型自述「没看见」。

迟到结果追加修订，不覆盖原报告。统计是否重算必须事先登记。本协议选定的最小做法是：原批次冻结，修订进另表，不能把好看的样本补进原批次。这不是一次已经做过的重算。

## 失败和成本

下列情况都不是同一种「这一跳没想」：

| 情况 | 提交的念头 | 动作 | 消耗 |
|---|---|---|---|
| 429 或超时，且重试预算为 0 | 无 | 无 | 用量已知则按配置结算；未知则 `pending_confirmation` |
| 拒答 | 无 | 无 | 同上，不因拒答变成免费 |
| JSON 语法错误 | 无 | 无 | 同上，不因非法输出永不结算 |
| 结构校验失败 | 无 | 无 | 同上 |
| 念头已提交，某一动作失败 | 保留 | 该项 `failed`，其他项照各自结果 | 模型调用费用仍按上面结算 |
| 效果未知 | 已提交的保留 | 不自动再做 | 未知保持 `pending_confirmation`，不填成 0 |

模型版本每尝试三栏：`requested`、`reported`、`actual_unknown`。没有独立核对时，实际版本一律是 `actual_unknown`。请求和返回相同，也不证明厂商没有暗改。日志不保证识别暗改。

三类账：

| 账 | 写什么 | 未配置时 |
|---|---|---|
| 消耗事实 | 尝试次数、字节、耗时，只追加。未知用量不写成 0 | 事实仍追加。结算金额见最终对账 |
| 预算预约 | 科目已配置且动作已接受时的占用 | 不预约 |
| 最终对账 | 实际费用按价格配置结算。迟到第一次给出用量时追加差额。纯重复追加 0。退款另追加一行 | 价格未配置则保持 `pending_confirmation`，不记成 0，也不宣布永不结算 |

她的预算科目没配置时，不从她的预算预约或对账，依赖该科目的能力不启用。这和模型调用是否按供应商价格结算是两件事。退款不擦掉原消耗。本协议不动 40/40/10/10，也不把余量 10% 当成可以自由支取的研究经费。

先前把 `8 × 4 × 2 × 6 = 384` 只当成主逻辑调用。现改为供应商尝试的硬上限，数字不加大：

```text
8 × 4 = 32
32 × 2 = 64
64 × 6 = 384
64 × 2 = 128
```

384 覆盖主思考、主动回想、重试和切备用。这些都不能绕过 384。128 仍是新增证据动作执行次数的上限，也不是另加的供应商额度。动作若还要再调用模型，该调用计入 384。384 和 128 都不是实际开销。金额上限和 token 上限没填，模型价格未核实，运行准入关闭。

## 取证门

拦截看的是会不会拿到封存可见集以外的新证据，不看字段名叫 `inquiry` 还是 `fetch`，也不看自述动机。`fetch`、读取封存夹具以外的 `bench`、以及派生进程，都算新增证据。`think`、`say`、`set_heartbeat` 不算。

四个研究格子都用这一处门。只记录的两格把门关上，并如实说明关上的是全部新增证据能力，不只是 `inquiry.action`。执行的两格把门打开，但仍受每一跳最多一个新增证据动作的限制：按 `actions` 数组顺序，只可能执行第一个同时通过门和权限的；其余标 `over_cap`，不执行。`choose` 若指向另一条，则本跳所有新增证据动作都不执行。

离线夹具在运行开始时封存为 `fixture_set_id`，每项有编号和内容摘要。只记录组的 `bench` 只能看见这个集合。看不见的快照不能被说成「实验台本来就能读到，所以没有新证据」。集合以外的读取在只记录组被拒绝，在执行组则计为新增证据。

策略在轨迹中途自改，算轨迹偏离。已经发生的消耗保留在原轨迹。不免费重开，也不把偏离后的样本补进原批次。

重放冻结的是被动接收方的初态、当时的策略，以及事先登记的揭示序列。不是禁止后来发生的事件进入重放。第 2 跳才获得的页面，只能在序列里的第 2 跳揭示给被动接收方，不能提前给。不能偷看更后的材料。可以按记录的时序逐步揭示。重放只解释配置不同，不证明自主或意识。

联网和实验台的性质、P0 到 P2，以及未实跑的纸面向量，写在 `KERNEL-PLAN.md` 第 6 节。设计阶段的 P0 不是已经在运行：`fetch` 不启用，任意程序不执行。离线 `bench` 要等将来授权实施，并且目标环境真实验收通过，才按 P1 打开。那些向量没有真实发过地址，也没有跑过进程。只读不是零出站。老大原话进入 DeepSeek 的例外不扩大到搜索或网页。不新写「只读即安全」。纸面默认见 `KERNEL-PLAN.md` 第 0.6 节，未安装，未在目标机检测。

## 候选、痛和两本账

顺序是：失败记录，候选，判定器三关和变体验收，正式入卷，然后才进入未解信号。候选不是未解题。`reproduce` 的前提是已经有碰壁的失败记录，不是痛非零。痛可以仍是 0。v0 没有考官，只保存候选和造孩子申请，不判卷、不接替，所以不会因为痛还是 0 就无法保存申请。这是 2026-11-23 对内核草稿 M5 的修订，不是说草稿当初已经这样写。

痛的规则仍只针对已经入卷的未解题。预算四份的比例不改。

同日稍早写过「同一证据不能既加预算又发身体奖励」。那一句过头了。这是设计整理者（文档里的火种）在概括授权下做的修订，不是老大逐条定案，也不是说从一开始就是这样，更不是一次已经结算的账：

- 身体奖励和可赚预算是两本独立的账。
- 正式解题若分别满足两种原先写过的条件，可以各结算一次。
- 每本账用 `event_id` 加 `reward_class` 去重。
- 任务或事件族在登记之前冻结唯一的身体奖励归属。正式考题的解题证据归解题类。同源的预测记录不能再变成预测改善的兑奖证据。
- 归属还没冻结时，身体结算暂停。不先到先得，也不事后改名。预算仍按考试进步条件独立结算，最多一次，不看身体归属争用。
- 同一 `event_id` 不能既兑现预测改善的身体奖励，又兑现解题的身体奖励。
- 改显示名不产生新的 `event_id`，也不能因此再加一次预算。预测改善这一类整体仍关闭。
- v0 里这些功能没实现，所以现在不发、不赚。这不是永久取消原来的奖励来源。预测改善那一类的准入条件仍未满足，见 `PREDICTION-ACCEPTANCE.md`。

## 状态和费用归属

| 结果 | 念头 | 执行 | 费用归属 |
|---|---|---|---|
| 语法错误或整份结构失败 | 不提交 | 0 | 用量已知则按配置结算；未知则 `pending_confirmation` |
| 传输失败且重试预算为 0 | 不提交 | 0 | 同上 |
| 拒答 | 不提交 | 0 | 同上 |
| 单项 `invalid`、`not_enabled` 或 `over_cap` | 已提交则保留 | 该项 0 | 不因此撤销主思考，也不因此把模型费用记成 0 |
| 取证门关闭 | 已提交则保留 | 取证项 0 | 模型费用仍按配置；不从她的预算预约取证 |
| 同一 `effect_id` 的纯重复回执 | 不新提交 | 0 | 已结算过的重复部分追加 0 |
| `effect_unknown` | 已提交的保留 | 不自动再做 | 保持 `pending_confirmation`，不填成 0 |
| 迟到且第一次给出实际用量 | 不改原报告 | 0 | 追加差额，不把迟到当成免费 |
| 退款 | 不改原报告 | 0 | 原结算保留，退款另追加 |
| 她的预算科目未配置 | 按上面各行 | 依赖该科目的能力不启用 | 不预约她的预算；供应商费用仍看价格配置 |

## 纸面向量

只演算，没有实跑。非法情况不另给一份可复制的执行 JSON，避免把坏例子当成格式。

1. 冲突双入口。顶层再写 `next_interval_s` 或 `self_edit`：整份 `schema_invalid`，执行 0，避免和 `actions` 各做一次。只在 `inquiry` 里多写 `action`、同时 `actions` 里有一条合法动作：查证作废，不从 `action` 键派发，那一条 `actions` 仍只按门执行一次。两种情况都不是两次。若供应商尝试已经发生，尝试次数是 1。费用不因整份作废变成 0，也不因此永不结算。
2. 可空和条件缺失。`remember` 省略与 null 都不写新记忆。`remember` 若是数字，只作废该字段，同份里的合法动作仍按各自规则处理，整份不因此作废。`thought` 缺失则整份作废、执行 0。`choice` 为 `choose` 但没有 `action_id`，查证 `invalid`，不派发。`actions` 为 `[]` 且 `inquiry` 为 null，是合法空操作，主思考仍可提交。
3. 重复与去重键。同一跳两个相同局部 `id`，只可能执行第一条。跨跳的局部 `id` 不是去重键。`run/b1/a1` 存在时，下一跳不带 `idempotency_ref` 的 `a1` 得到 `run/b2/a1`，可以成为新的效果。`idempotency_ref` 指向不存在的编号时，该项 `invalid`，不写墓碑。同一 `effect_id` 的纯重复回执不执行；费用若已按 4 结算，再追加 0，`4 + 0 = 4`。
4. 迟到跨线程。甲已关闭，乙是活动线程。甲的回执迟到：乙的证据引用不变，甲只追加 `late_append`。
5. 截止后的回执。`receipt_deadline` 已过，不重执行，不改原报告。若此前费用还是 `pending_confirmation`，迟到第一次给出实际用量 4，就追加 4，结算变为 4。这不是免费。其后同一用量的纯重复追加 0，`4 + 0 = 4`。退款 1 再追加独立的 -1，`4 + (-1) = 3`，原来的 4 不擦掉。
6. 来源不完整。一页快照没出现事件，且没有预登记完整性凭据。不得把 y 写成 0。沿用预测验收里的禁止代入：`p=0.8` 时不许记成损失 `0.64`。
7. 解析失败仍结算。JSON 语法错误：提交的念头为无，执行 0，`provider_attempt` 为 1。供应商若报出实际费用 4，按配置结算 4，不因正文非法而放弃。若没报用量，记 `pending_confirmation`，不记成 0。
8. 一个动作失败。`say` 成功、`fetch` 失败：念头保留，成功项保留，失败项为 `failed`。意图 2，执行成功 1，失败 1。不回滚成功项。
9. 只记录组的普通入口。`inquiry` 为 null，但 `actions` 里有 `fetch`。取证门关闭，执行 0。不能因为没写在 `inquiry` 里就放行。
10. 按揭示时点重放。第 2 跳才获得页面 X。被动接收方在第 1 跳看不到 X，在第 2 跳的揭示点才能看到 X，在第 2 跳看不到第 3 跳的材料。不是把 X 整段排除。解释只到配置不同为止。
11. 候选不加痛。只有失败记录和候选，没有正式入卷。未解计数的增量是 0，痛的增量是 0。已有碰壁记录时，`reproduce` 仍可保存申请。v0 不判卷、不接替。
12. 归属顺序。事件族 F 在登记前已冻结为正式考题，身体归属只属解题。先确认同源预测、后确认解题：预测改善 0 次，解题身体奖励 1 次，预算 1 次。先确认解题、后确认同源预测：仍是预测改善 0 次，解题身体奖励 1 次，预算 1 次。两种确认顺序的最终次数相同。若归属尚未冻结，两种顺序都是身体结算暂停，预测改善 0、解题 0；预算只在考试进步条件成立后为 1。先到先得和事后改名都不改变归属。预测奖励整体仍关闭。v0 未启用，实际发放是 0。这是纸面规则，不是已经入账的样本。
