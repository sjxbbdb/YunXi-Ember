# 节拍输出合同 beat-output/1（纸面，2026-11-23）

> 项目是 YunXi-Ember。本文件是输出、回执、取证门、费用归属和痛的入卷顺序的唯一协议。设计整理者在老大持续授权下写下。授权不是逐条确认，下面也不是已经跑过的结果。
> 其他文档只引用本文件，不再各写一份可执行 JSON。若草稿里的旧例子和本文件不一致，以本文件为准。
> 全局模型路由和技术选型本轮不拍板。没有调用模型，没有写程序，没有部署，没有付费。

## 版本和迁移

执行只认 `beat-output/1`，对象里的 `v` 必须是 `1`。

2026-10-27 唤醒框草稿把间隔写在 `next_interval_s`，把自我描述修改写在 `self_edit`，动作又写在 `actions`。2026-11-23 查证草稿又在 `inquiry.action` 里放了第二个动作。两处都会造成一次输出执行两次。本版删掉这些并行入口，不采用「两个字段都在时挑一个」的规则，避免实现者自己猜。

迁移只有一条：旧字段不再出现。间隔只写成 `actions` 里的 `set_heartbeat`。自我描述修改只写成 `edit_self`。查证只引用本跳 `actions` 里已有的 `id`，自己不带动作对象。顶层出现未知键，整份输出作废，一个动作也不执行。`inquiry` 里出现未知键 `action`，这份查证作废，也不从那个键派发。

## 关联

每条回执至少带 `run_id`、`beat_id`、`request_id`。与查证或证据有关时再带 `thread_id`、`source_id`。炉子接受动作后生成 `effect_id`，形如 `run_id/beat_id/action.id`。本代不能改写已经写下的 `effect_id`。

四层不要混用：

| 层 | 是什么 | 不是什么 |
|---|---|---|
| `beat` | 一个决策槽，含一次主思考 | 不是一次供应商 HTTP |
| `logical_call` | 槽内的一次预定调用：主思考，或一次主动回想 | 不是恰好全局只有一次 |
| `provider_attempt` | 对供应商的一次实际尝试，含 429、超时、切备用 | 不是「这一跳没想」 |
| `action_execution` | 一个已接受动作的一次效果尝试 | 不是第二份输出 |

一跳若被启动，至少有一次主思考 `logical_call`。主动回想可以另加 `logical_call`。总计不必是 1。没有事先写明的有限重试配置时，重试预算是 0，不自动再试。

## 唯一输出

顶层只许这些键。`v`、`context_version`、`thought`、`actions` 必填。`remember`、`expect_note`、`inquiry`、`prediction` 可空：省略和 JSON `null` 相同，表示没有这项。

| 键 | 必填 | 空值 | 不合规则时 |
|---|---|---|---|
| `v` | 是 | 不允许 null | 整份 `schema_invalid`，不执行 |
| `context_version` | 是 | 必须等于本跳上下文里的版本号 | 不一致则整份 `schema_invalid` |
| `thought` | 是 | 允许 `""`，不允许 null | 缺失或 null 则整份 `schema_invalid` |
| `actions` | 是 | 允许 `[]`，不允许 null | 不是数组则整份 `schema_invalid` |
| `remember` | 否 | 省略、null、`""` 都表示不新记 | 不是字符串则该字段作废，不执行动作 |
| `expect_note` | 否 | 省略或 null 表示没有自由文本 | 只存文本，不评分，不派发 |
| `inquiry` | 否 | 省略或 null 表示本跳不处理查证 | 见下节；不作第二次派发 |
| `prediction` | 否 | 省略或 null 表示没有预测承诺 | 评分未启用时只存原文并标 `not_enabled`，不接通评分或奖励，也不变成 y |

`actions` 的每一项：

| 键 | 规则 |
|---|---|
| `id` | 本跳内必填、唯一。重复的后项标 `duplicate_in_beat`，不执行 |
| `type` | 只认 `think`、`fetch`、`bench`、`say`、`reproduce`、`appeal`、`set_heartbeat`、`edit_self` |
| `interval_s` | 仅 `set_heartbeat` 必填，且须落在本跳给出的闭区间内 |
| `text` | `say` 与 `edit_self` 必填。`edit_self` 还须不超过本跳字数上限 |
| `target` | 仅 `fetch` 必填 |
| `idempotency_ref` | 可省略。若填写，必须是本 `run_id` 里已有的 `effect_id`，然后不执行、不第二次记账 |
| `retry_of` | 可省略。重试预算为 0 时填写则该项 `invalid`。预算大于 0 时也要计入硬封顶，不另开额度 |

未知的动作键使该项 `invalid`，不连坐其他项。条件字段缺失同样只使该项 `invalid`。

`inquiry` 若是对象，`choice` 必填，只认 `propose`、`choose`、`shelve`、`close`、`skip`。`choose` 是这一跳自己的选择，不是老大的批准，也不能扩大已经有的权限。

| choice | 另外必填 | 执行 |
|---|---|---|
| `propose`、`choose` | `cites` 非空，且每一项都是本跳上下文里已有的来源；`question`；`would_change_if` | 不直接执行 |
| `choose` | 再加 `action_id`，且等于本跳 `actions` 里的某个 `id` | 仍只由那一条 `actions` 执行一次 |
| `shelve`、`close`、`skip` | 无 | `action_id` 必须省略或 null，否则这份查证 `invalid` |

没有可引用的外部材料时，`propose` 和 `choose` 不成立。此时合法的是 `inquiry` 为 null。不补种子题。

`prediction` 在评分功能启用之前，任何非空值都只是原文归档，状态 `not_enabled`。不计算 Brier，不发身体奖励，不增加可花预算，不制造痛题。启用条件仍以 `PREDICTION-ACCEPTANCE.md` 为准。本文件不复制那份字段合同。

## 写入顺序和原子性

1. 供应商尝试一旦发生，就追加消耗事实。这一步不因为后面的解析失败而撤销。
2. 追加不可变回执，保存原始正文、`requested`、`reported`、`actual_unknown`。
3. 做语法和结构校验。
4. 整份 `schema_invalid` 时停在这里：不提交念头，不执行动作。回执和消耗保留。
5. 整份合法时，念头、`remember`、`expect_note`、查证状态和动作意图同一次提交。提交不成则都不留下，但仍保留第 1 步的消耗。
6. 提交成功后再按门逐项执行。一项失败不回滚念头，也不回滚其他项的结果。
7. 意图已经提交、效果回执没有回来，标 `effect_unknown`。不盲目重试。外部副作用不能保证恰好一次。

线程里的叙述，包括念头和查证问题的后改，可以由本代按 `EXPLORATION-PLAN.md` 变更。炉子回执、成本行、证据引用所指向的来源，本代不能覆盖。更正只追加。

## 异步

关闭线程甲、建起线程乙之后，甲的迟到回执只能追加到甲，不能写入乙。同一 `request_id` 或同一 `effect_id` 的再次到达不执行、不第二次扣账。乱序到达不把旧动作再执行一遍。

四个时间分开，不能互相代替：

| 名称 | 作用 |
|---|---|
| `event_window` | 预测事件可能发生的区间，封存时由炉子写入 |
| `receipt_deadline` | 这一次尝试的回执何时起算迟到 |
| `observation_complete` | 预登记数据源给出的完整性凭据 |
| `settlement_status` | `unconfigured`、`not_settled`、`settled`、`rejected_duplicate` 之一 |

单页快照里没看见事件，不能证明事件没发生，不能记 y=0。只有预登记数据源给出完整性凭据，并且凭据说明观察完整且事件没有发生，才可以 y=0。结果在提交前已经泄漏，准入直接失败，不能靠模型自述「没看见」。

迟到结果追加修订，不覆盖原报告。统计是否重算必须事先登记。本协议选定的最小做法是：原批次冻结，修订进另表，不能把好看的样本补进原批次。这不是一次已经做过的重算。

## 失败和成本

下列情况都不是同一种「这一跳没想」：

| 情况 | 提交的念头 | 动作 | 消耗 |
|---|---|---|---|
| 429 或超时，且重试预算为 0 | 无 | 无 | 保留该次尝试 |
| 拒答 | 无 | 无 | 保留 |
| JSON 语法错误 | 无 | 无 | 保留 |
| 结构校验失败 | 无 | 无 | 保留 |
| 念头已提交，某一动作失败 | 保留 | 该项 `failed`，其他项照各自结果 | 保留 |
| 效果未知 | 已提交的保留 | 不自动再做 | 已发生的保留，未知账不填成 0 |

模型版本每尝试三栏：`requested`、`reported`、`actual_unknown`。没有独立核对时，实际版本一律是 `actual_unknown`。请求和返回相同，也不证明厂商没有暗改。日志不保证识别暗改。

三类账：

| 账 | 写什么 | 未配置时 |
|---|---|---|
| 消耗事实 | 尝试次数、字节、耗时，只追加 | 仍可记事实，但不能当成扣款 |
| 预算预约 | 科目已配置且动作已接受时的占用 | 不预约 |
| 最终对账 | 科目已配置后的结算，含供应商退款的追加行 | 不对账，能力不启用 |

退款追加一行，不擦掉原消耗。未知账保持未知。本协议不动 40/40/10/10，也不把余量 10% 当成可以自由支取的研究经费。科目没配置，对应能力不能启用。

先前把 `8 × 4 × 2 × 6 = 384` 只当成主逻辑调用。现改为供应商尝试的硬上限，数字不加大：

```text
8 × 4 = 32
32 × 2 = 64
64 × 6 = 384
64 × 2 = 128
```

384 覆盖主思考、主动回想、重试和切备用。这些都不能绕过 384。128 仍是新增证据动作执行次数的上限，也不是另加的供应商额度。动作若还要再调用模型，该调用计入 384。384 和 128 都不是实际开销。金额上限和 token 上限没填，模型价格未核实，运行准入关闭。

## 取证门

拦截看的是会不会拿到封存可见集以外的新证据，不看字段名叫 `inquiry` 还是 `fetch`，也不看自述动机。`fetch`、读取封存夹具以外的 `bench`、以及派生进程，都算新增证据。`think`、`say`、`set_heartbeat` 不算。

四个研究格子都用这一处门。只记录的两格把门关上，并如实说明关上的是全部新增证据能力，不只是 `inquiry.action`。执行的两格把门打开，但仍受每一跳最多一个新增证据动作的限制：按 `actions` 数组顺序，只可能执行第一个同时通过门和权限的；其余标 `over_cap`，不执行。`choose` 若指向另一条，则本跳所有新增证据动作都不执行。

离线夹具在运行开始时封存为 `fixture_set_id`，每项有编号和内容摘要。只记录组的 `bench` 只能看见这个集合。看不见的快照不能被说成「实验台本来就能读到，所以没有新证据」。集合以外的读取在只记录组被拒绝，在执行组则计为新增证据。

策略在轨迹中途自改，算轨迹偏离。已经发生的消耗保留在原轨迹。不免费重开，也不把偏离后的样本补进原批次。

重放从第一个新增证据之前的封存状态开始，冻结当时的接收策略和可见输入顺序。封存之后才出现的材料不得进入重放。重放只解释配置不同，不证明自主或意识。

联网和实验台分别准入。下面各项本轮没有验收，未验收的能力不启用。本轮不挑选隔离技术，也不宣称测试已经通过：

- 地址解析
- 重定向后再解析
- 出站数据边界。GET 的地址和查询也是数据，不是无副作用证明
- 不可信页面与预算、实验台申请、动作意图的隔离
- 进程树的资源约束。事后杀掉不能冒充事前的聚合限额

不新写「只读即安全」。

## 候选、痛和两本账

顺序是：失败记录，候选，判定器三关和变体验收，正式入卷，然后才进入未解信号。候选不是未解题。v0 没有考官时，里程碑只保存候选和造孩子申请，痛保持原值，不从 0 变成非 0。这是 2026-11-23 对内核草稿 M5 的修订，不是说草稿当初已经这样写。

痛的规则仍只针对已经入卷的未解题。预算四份的比例不改。

同日稍早写过「同一证据不能既加预算又发身体奖励」。那一句过头了。老大这次的定案是修订，不是说从一开始就是这样，也不是一次已经结算的账：

- 身体奖励和可赚预算是两本独立的账。
- 正式解题若分别满足两种原先写过的条件，可以各结算一次。
- 每本账用 `event_id` 加 `reward_class` 去重。
- 同一 `event_id` 不能既兑现预测改善的身体奖励，又兑现解题的身体奖励。
- 改显示名不产生新的 `event_id`，也不能因此再加一次预算。
- v0 里这些功能没实现，所以现在不发、不赚。这不是永久取消原来的奖励来源。预测改善那一类的准入条件仍未满足，见 `PREDICTION-ACCEPTANCE.md`。

## 状态和费用归属

| 结果 | 念头 | 执行 | 费用归属 |
|---|---|---|---|
| 语法错误或整份结构失败 | 不提交 | 0 | 消耗事实保留；不对账 |
| 传输失败且重试预算为 0 | 不提交 | 0 | 消耗事实保留 |
| 拒答 | 不提交 | 0 | 消耗事实保留 |
| 单项 `invalid` 或 `over_cap` | 已提交则保留 | 该项 0 | 不因该项再记一次模型调用 |
| 取证门关闭 | 已提交则保留 | 取证项 0 | 消耗事实保留；不预约取证预算 |
| 重复 `effect_id` 或重复回执 | 不新提交 | 0 | 追加 0 |
| `effect_unknown` | 已提交的保留 | 不自动再做 | 未知账保持未知 |
| 迟到回执 | 不改原报告 | 0 | 追加 0；修订进另表 |
| 退款 | 不改原报告 | 0 | 原消耗保留，退款另追加 |
| 科目未配置 | 按上面各行 | 收费能力不启用 | 无预约、无对账 |

## 纸面向量

只演算，没有实跑。非法情况不另给一份可复制的执行 JSON，避免把坏例子当成格式。

1. 冲突双入口。顶层再写 `next_interval_s` 或 `self_edit`：整份 `schema_invalid`，执行 0，避免和 `actions` 各做一次。只在 `inquiry` 里多写 `action`、同时 `actions` 里有一条合法动作：查证作废，不从 `action` 键派发，那一条 `actions` 仍只按门执行一次。两种情况都不是两次。若供应商尝试已经发生，消耗仍是 1，不是 0。
2. 可空和条件缺失。`remember` 省略与 null 都不写新记忆。`thought` 缺失则整份作废、执行 0。`choice` 为 `choose` 但没有 `action_id`，查证 `invalid`，不派发。`actions` 为 `[]` 且 `inquiry` 为 null，是合法空操作。
3. 重复动作和重复回执。同一跳两个相同 `id`，只可能执行第一条。随后又来一次同一 `effect_id` 的回执：执行仍是 1，消耗追加 0。`1 + 0 = 1`。
4. 迟到跨线程。甲已关闭，乙是活动线程。甲的回执迟到：乙的证据引用不变，甲只追加 `late_append`。
5. 截止后的回执。`receipt_deadline` 已过，状态保持超时。迟到正文追加到另表，不改原报告，不重执行，不第二次记账。
6. 来源不完整。一页快照没出现事件，且没有预登记完整性凭据。不得把 y 写成 0。沿用预测验收里的禁止代入：`p=0.8` 时不许记成损失 `0.64`。
7. 解析失败仍有成本。JSON 语法错误：提交的念头为无，执行 0，`provider_attempt` 为 1，消耗保留。
8. 一个动作失败。`say` 成功、`fetch` 失败：念头保留，成功项保留，失败项为 `failed`。意图 2，执行成功 1，失败 1。不回滚成功项。
9. 只记录组的普通入口。`inquiry` 为 null，但 `actions` 里有 `fetch`。取证门关闭，执行 0。不能因为没写在 `inquiry` 里就放行。
10. 关闭后重放。重放输入停在第一个新增证据之前的封存顺序。其后的页面不出现。解释只到配置不同为止。
11. 候选不加痛。只有失败记录和候选，没有正式入卷。未解计数的增量是 0，痛的增量是 0。
12. 两本账各去重。同一 `event_id` 可以各有一次解题身体奖励和一次考试预算，若两种原条件都成立。同一 `event_id` 再要预测改善的身体奖励，则 `rejected_duplicate`。改名后 `event_id` 仍是原来的。v0 未实现，所以向量本身的发放次数也是 0。这不是已经入账的样本。

## 运行阻塞

协议语义本轮已经写死，但下面未定，所以不能启用相应能力，也不能开行为试验：

- 金额上限、token 上限、模型价格
- 收费科目未配置时的任何扣款
- 联网四项验收和实验台进程树验收
- 重试若需要非 0 的有限次数，次数本身还没登记
- 预测奖励的样本量、最小改善和统计规则
